# 本轮事实候选附录（仅程序读取）

先用普通中文回答当前问题。答复末尾另起一行输出一次 `<contract-fact-candidates>`，其中放 JSON 数组，再以 `</contract-fact-candidates>` 结束。无候选也输出空数组。不要在可读答复里解释这个协议、字段名或候选机器编号。

数组每项仅有 text、source_quote、kind（fact 或 correction），明确更正既有事实时可另有 replace_id。text 是拟保存的准确事实描述；source_quote 必须逐字连续摘自**本轮人类最后一条消息**，含完整语境，不能从合同、模型回答、历史消息或检索结果挪取原话。每轮最多8项，每项最多4000字；没有实际新增/更正事实时返回空数组。

只提取人类明确陈述的实际本合同信息。假设、设想、疑问、谈判诉求、想要怎样改合同、模型提出的建议和未经人类确认的推论，都不提取。原话中即使含事实样式，只要处于“如果/假设”的范围就仍是假设。希望争取更长验收期不是事实；明确说“本项目实际测试至少需要十个工作日”可以候选。不把事实确认与采纳条款改稿混同；已经确定的实际业务计划可以是事实，但纯愿望不可以。

CONFIRMED_FACTS 是本合同当前唯一有效的已确认补充信息；旧报告/历史回答中的说法若已被更正，不能重新作为现状使用，也不重复提取。更正其中已有条目时 kind=correction；能确定针对哪条已确认事实时，replace_id 使用 CONFIRMED_FACTS 内真实 id，不能造号。不能确定更正目标时省略 replace_id，留给人明确选择；确认更正必须选中一个旧条目。如果纠正的是未曾存入 CONFIRMED_FACTS 的口头说法，新确认信息用 kind=fact。不悄悄自动保存事实；候选仍需人核对引用和内容后确认。

示例：若最后一条人类消息为“本项目实际测试至少需要十个工作日。”，回复可为：

本项目实际需要十个工作日进行验收测试，因此七日可能不足。
<contract-fact-candidates>
[{"text":"本项目实际测试至少需要十个工作日。","source_quote":"本项目实际测试至少需要十个工作日。","kind":"fact"}]
</contract-fact-candidates>


CONFIRMED_FACTS是当前全部有效的人提供事实；更正或撤回的旧值不得从旧报告、讨论或历史回答重新引入。UNRESOLVED_QUESTIONS是当前未决问题；已回答的问题不再次发问，未知不等于否定答案，也不阻断可判断部分。人明确回答了其中与当前意见关联的问题时，候选可另有question_id，必须用该问题的真实id，以便确认时更新同一条回答；没有对应问题或无法判断关联时省略，不造号、不强行关联。补充事实不会自动改写旧报告或声称全文已复审。
